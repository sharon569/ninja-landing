גוגל אומר ש-Core Web Vitals זה רק "טיברייקר". זה **שקר חברה**. אם האתר שלך איטי, לא תהיה במקום הראשון. נקודה.

## ה-3 מדדים

### 1. LCP — Largest Contentful Paint
**מה זה:** כמה זמן עובר עד שהאלמנט הכי גדול בעמוד נטען.
**יעד:** מתחת ל-**2.5 שניות**.
**מה לעשות:** דחיסת תמונות (WebP/AVIF), preload לפונטים, CDN.

### 2. INP — Interaction to Next Paint
**מה זה:** כמה זמן לוקח לדף להגיב לאינטראקציה (קליק, גלילה, הקלדה).
**יעד:** מתחת ל-**200ms**.
**מה לעשות:** הקטנת JavaScript, defer scripts, ביטול בלוקרים.

### 3. CLS — Cumulative Layout Shift
**מה זה:** עד כמה הדף "קופץ" בזמן הטעינה.
**יעד:** מתחת ל-**0.1**.
**מה לעשות:** תמיד להגדיר width/height לתמונות, להימנע מבאנרים שנכנסים פתאום.

## איך לבדוק

1. **Google PageSpeed Insights** (chrome.google.com/pagespeed) — דוח מהיר ומלא
2. **Search Console → Core Web Vitals** — רואה איזה דפים נכשלים
3. **Chrome DevTools → Lighthouse** — דיבוג מקומי

## הטעות הכי נפוצה

לקוחות מודדים את ה-LCP בדף הבית ושמחים שהוא 1.8s. אבל הם לא בודקים את **דפי המוצר** — שם 80% מהתנועה שלך, ושם ה-LCP בדרך כלל 4-6 שניות.

**תבדוק את כל סוגי הדפים. כל אחד.**

## מקרה מבחן

לקוח קמעונאי הגיע אלינו עם:
- LCP: 5.4s
- INP: 380ms
- CLS: 0.42

אחרי 14 יום של אופטימיזציה (תמונות → AVIF, defer של 6 scripts, dimensions לכל תמונה):
- LCP: **1.6s**
- INP: **120ms**
- CLS: **0.05**

תנועה אורגנית עלתה ב-**42% תוך 8 שבועות**. בלי תוכן חדש. בלי קישורים חדשים. רק מהירות.
