# מדריך למפעיל — Ninja SEO Bot

## מה זה?

בוט Telegram שמנהל את מערכת ה-SEO. במקום לשבת מול הדשבורד בדפדפן, אתה שולח פקודות בטלגרם והמערכת עובדת — סריקות, ניתוח, אסטרטגיה, תוכן, לוח זמנים. אתה רק מאשר.

---

## התקנה ראשונית

### 1. יצירת בוט Telegram

1. פתח את Telegram וחפש `@BotFather`
2. שלח `/newbot`
3. בחר שם (למשל: `Ninja SEO Bot`)
4. בחר username (למשל: `ninja_seo_prod_bot`)
5. תקבל **Bot Token** — שמור אותו

### 2. קבלת Chat ID

1. שלח הודעה כלשהי לבוט החדש
2. פתח בדפדפן:
   ```
   https://api.telegram.org/bot<TOKEN>/getUpdates
   ```
3. חפש את `"chat":{"id":` — המספר הזה הוא ה-Chat ID שלך

### 3. הגדרת משתני סביבה ב-Vercel

ב-Vercel Dashboard → ninja-analyzer → Settings → Environment Variables:

| משתנה | ערך | סביבה |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | הטוקן מ-BotFather | Production |
| `TELEGRAM_CHAT_ID` | ה-Chat ID שלך | Production |
| `TELEGRAM_ENABLED` | `true` | Production |
| `TELEGRAM_ALLOWED_USER_IDS` | ה-Chat ID שלך (ניתן להוסיף כמה, מופרדים בפסיק) | Production |
| `TELEGRAM_WEBHOOK_SECRET` | מחרוזת אקראית כלשהי | Production |
| `ANTHROPIC_API_KEY` | מפתח API של Anthropic (לכתיבת תוכן AI) | Production |
| `PUBLIC_ANALYZER_URL` | `https://seo.samp.ninja` | Production |

### 4. רישום Webhook

לאחר הפריסה, הפעל בטרמינל:

```bash
curl "https://api.telegram.org/bot<TOKEN>/setWebhook" \
  -d "url=https://seo.samp.ninja/api/telegram/webhook" \
  -d "secret_token=<TELEGRAM_WEBHOOK_SECRET>" \
  -d "drop_pending_updates=true"
```

### 5. הרצת מיגרציות

המיגרציות אמורות לרוץ אוטומטית בפריסה. אם לא, הרץ:

```bash
psql "$DIRECT_URL" -f prisma/migrations/20260522000000_phase16_foundation/migration.sql
psql "$DIRECT_URL" -f prisma/migrations/20260522010000_phase16_keyword_discovery/migration.sql
psql "$DIRECT_URL" -f prisma/migrations/20260522020000_phase16_pagespeed/migration.sql
psql "$DIRECT_URL" -f prisma/migrations/20260522030000_phase16_content_calendar/migration.sql
psql "$DIRECT_URL" -f prisma/migrations/20260522040000_phase16_content_drafts/migration.sql
```

## פקודות Telegram

### פקודות מידע (קריאה בלבד)

| פקודה | מה עושה |
|---|---|
| `/help` | רשימת כל הפקודות |
| `/clients` | רשימת כל הלקוחות עם ציון בריאות |
| `/status <לקוח>` | סטטוס מפורט — הזדמנויות, ממצאים, מילות מפתח, GSC |
| `/opps <לקוח>` | הזדמנויות פתוחות עם כפתורי אישור/דחייה |
| `/plan <לקוח>` | תוכנית עבודה עם כפתורי אישור קבוצות |
| `/discover <לקוח>` | מילות מפתח חדשות מ-GSC שלא בבנק |
| `/calendar <לקוח>` | לוח תוכן — פוסטים מתוזמנים |
| `/speed <לקוח>` | ציון מהירות + Core Web Vitals |

### פקודות פעולה

| פקודה | מה עושה |
|---|---|
| `/scan <לקוח>` | מריץ סריקה חדשה של האתר |
| `/refresh <לקוח>` | רענון מלא — GSC + אודיט + הזדמנויות + אסטרטגיות + תוכנית עבודה |
| `/sync <לקוח>` | סנכרון Google Search Console |
| `/write <brief ID>` | יצירת תוכן AI מבריף קיים |
| `/schedule <לקוח>` | תזמון אוטומטי של בריפים מאושרים |

### כפתורים (לחיצה על כפתורי Inline)

| כפתור | מה עושה |
|---|---|
| ✅ (בהזדמנויות) | מאשר הזדמנות — סטטוס משתנה ל-"מאושר" |
| ❌ דחה | דוחה הזדמנות |
| ✅ אשר Safe Meta | מאשר קבוצת Safe Meta בתוכנית → יוצר בריפים → מתזמן |
| ✅ אשר Quick Wins | אותו דבר לקבוצת Quick Wins |
| ➕ (בגילוי מילות מפתח) | מוסיף מילת מפתח לבנק → מפעיל ניתוח אוטומטי |
| ⏭ דלג | דוחה הצעת מילת מפתח |
| 📊 (בכרטיס לקוח) | מציג סטטוס מפורט |

## הזרימה היומית

### בוקר — בדיקת מצב

```
/clients
```

רואים את כל הלקוחות עם ציון בריאות. לוחצים על לקוח שצריך תשומת לב.

### כשמוסיפים מילות מפתח

כשלקוח שולח מילות מפתח חדשות, מוסיפים אותן דרך הדשבורד (ממשק האינטרנט). המערכת מפעילה אוטומטית:
- בדיקה ב-GSC
- חישוב אסטרטגיה
- יצירת בריפים
- בניית תוכנית עבודה

### אישור תוכנית עבודה

```
/plan <לקוח>
```

לוחצים על **"✅ אשר Safe Meta"** — המערכת:
1. מכינה בריפים (כותרות, תיאורים, מבנה תוכן)
2. מאשרת אותם
3. מתזמנת אותם בלוח התוכן

### צפייה בלוח

```
/calendar <לקוח>
```

רואים מה מתוזמן לשבוע הקרוב.

### גילוי מילות מפתח חדשות

```
/discover <לקוח>
```

המערכת סורקת את כל הנתונים ב-Search Console ומציעה מילות מפתח שלא בבנק. לוחצים ➕ להוסיף.

### יצירת תוכן

```
/write <brief ID>
```

המערכת כותבת תוכן בעברית לפי הבריף (כותרת, מבנה, מילות מפתח, קישורים פנימיים). התוכן נשמר כטיוטה לסקירה.

| פעולה | מתי |
|---|---|

| חישוב אסטרטגיות | אחרי כל רענון |
| בניית תוכנית עבודה | אחרי כל רענון |

## מה המערכת לא עושה לבד

| פעולה | צריך אישור |
|---|---|
| אישור הזדמנויות | ✅ כפתור בטלגרם |
| אישור תוכנית עבודה | ✅ כפתור בטלגרם |
| הוספת מילות מפתח | ➕ כפתור בטלגרם |
| ביצוע שינויים באתר | רק מהדשבורד — לא מטלגרם |
| Rollback | רק מהדשבורד — לא מטלגרם |

## דף Dev (לפיתוח ובדיקות בלבד)

כתובת: `/dev`

- **Environment Config** — בדיקת משתני סביבה
- **Job Queue** — צפייה בעבודות, הפעלת Drain ידני
- **Notifications** — לוג הודעות שנשלחו

הדף משתמש בלקוח בדיקות ייעודי ("🧪 Test Client (Dev)") — לא נוגע בלקוחות אמיתיים.

## טיפים

- **שם לקוח** בפקודות: מספיק חלק מהשם. `/status lev` ימצא את "Levizon Market".
- **Brief ID**: מופיע בדשבורד תחת הבריפים של הלקוח.
- **תוכן AI**: התוכן נשמר כטיוטה. תמיד יש לעבור עליו לפני פרסום.
- **מהירות**: צריך להגדיר `PSI_ENABLED=true` ו-`PSI_API_KEY` כדי לקבל נתוני מהירות.
- **לוח תוכן**: ברירת מחדל 2 פוסטים בשבוע (ראשון + רביעי). ניתן לשנות בהגדרות הלקוח.
